# Afghan Connect — راهنمای اجرای نسخه تحویلی

## پورت‌ها
- Frontend (Vite): `http://localhost:5173`
- Backend (Express): `http://localhost:5000`
- API Base URL: `http://localhost:5000/api/v1`
- Health check: `http://localhost:5000/api/v1/health`
- PostgreSQL پیش‌فرض: `localhost:5432`، دیتابیس `afghan_connect`

## پیش‌نیازها
- Node.js **22.22 یا بالاتر** (نسخه فعلی `react-router` در این پروژه این حداقل را می‌خواهد)
- npm
- PostgreSQL 14 یا بالاتر

## راه‌اندازی دیتابیس تازه
1. در PostgreSQL دیتابیس `afghan_connect` را بسازید.
2. فایل `database/schema.sql` را روی دیتابیس خالی اجرا کنید.
3. سپس `database/seed.sql` را اجرا کنید.

برای دیتابیسی که از نسخه قدیمی‌تر پروژه ساخته شده، ابتدا نسخه پشتیبان بگیرید، داده‌های تکراری پرداخت‌های باز را بررسی کنید و سپس در صورت نیاز فایل `database/migrations/001_one_open_payment_per_order.sql` را یک‌بار اجرا کنید. این Migration در صورت وجود بیش از یک تراکنش `pending` یا `successful` برای یک سفارش عمداً متوقف می‌شود.

## راه‌اندازی Backend
```bash
cd backend
cp .env.example .env
```
مقادیر واقعی PostgreSQL و `JWT_SECRET` را در `backend/.env` تنظیم کنید. `JWT_SECRET` باید حداقل ۳۲ کاراکتر تصادفی باشد. سپس:
```bash
npm install
npm run dev
```

## راه‌اندازی Frontend
در ترمینال دوم:
```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```
مقدار `VITE_API_BASE_URL` باید `http://localhost:5000/api/v1` باشد. برای تغییر شماره تماس، `VITE_CONTACT_PHONE` را مقداردهی کنید. در حال حاضر شماره تماس واقعی در پروژه تعریف نشده است.

## تست‌های انجام‌شده در محیط تحویل
- بررسی نحوی تمام فایل‌های Backend با `node --check`: موفق
- بررسی نحوی تمام فایل‌های JS/JSX فرانت‌اند با TypeScript compiler در حالت parse-only: موفق
- تست‌های مستقل وضعیت سفارش و تحویل (`orderState.test.js`): ۳ تست موفق
- تست `auth.test.js`: در این محیط اجرا نشد؛ وابستگی `pg` نصب نبود.
- `npm install` فرانت‌اند در محیط تحویل به timeout خورد؛ بنابراین `npm run build` قابل اجرا و تأیید نبود.
- اتصال واقعی به PostgreSQL و تست End-to-End مرورگر انجام نشده است؛ این موارد باید روی سیستم توسعه با تنظیمات دیتابیس واقعی اجرا شوند.

## قرارداد و محدودیت‌های واقعی Backend
- ثبت‌نام عمومی فقط حساب `customer` می‌سازد؛ نقش فروشنده و پیک از مسیر درخواست و تأیید مدیر فعال می‌شود.
- آپلود تصویر: `POST /api/v1/uploads/image`، فیلد multipart با نام `image`، حداکثر ۵ مگابایت و فرمت‌های JPG/PNG/WEBP/GIF.
- چت REST + polling است؛ WebSocket پیاده‌سازی نشده است.
- درگاه پرداخت بانکی/آنلاین و webhook واقعی وجود ندارد. Frontend پرداخت را موفق اعلام نمی‌کند.
- موقعیت‌یابی زنده پیک و محاسبه هزینه ارسال پویا وجود ندارد؛ هزینه ارسال فعلی در Backend صفر است.
- بازیابی رمز، OTP و تأیید ایمیل/شماره، ذخیره‌سازی ابری فایل و صفحه عمومی فروشنده با endpoint مستقل در Backend موجود نیستند.
- متن کالاها و خدمات در دیتابیس فعلی یک‌زبانه است؛ ترجمه UI به معنی ترجمه خودکار محتوای ثبت‌شده کاربران نیست.
- API فعلی endpoint مدیریتی برای moderation نظرها ارائه نمی‌کند.

## نکات نسخه فرانت‌اند
- صفحه دسته‌بندی‌ها اضافه شده است.
- انتخاب زبان دری/پشتو/انگلیسی، ذخیره زبان، تنظیم `lang` و `dir`، انتخاب تم روشن/تاریک و ذخیره تم اضافه/تکمیل شده است.
- بازیابی نقش کاربر از API اصلاح شد: endpoint `GET /users/me` اکنون `role_name` را از جدول roles برمی‌گرداند؛ نقش از localStorage به‌عنوان منبع مجوز استفاده نمی‌شود.
- پنل مدیر اکنون فهرست و ایجاد/فعال‌سازی/غیرفعال‌سازی کوپن‌ها را از endpoint واقعی `/coupons` مدیریت می‌کند.
- ترجمه UI در این نسخه هنوز در همه صفحه‌ها، پیام‌های اعتبارسنجی، وضعیت‌ها و فرم‌های داشبورد کامل و یکدست نشده است. این بخش نیازمند دور نهایی ترجمه و بازبینی انسانی دری و پشتو است.

## اجرای یک‌جای پروژه بدون pgAdmin (برای لپ‌تاپ هم‌صنفی)
pgAdmin فقط ابزار مدیریت گرافیکی است و خودِ سرور PostgreSQL نیست؛ نصب آن لازم نیست. برای اجرای آماده، Docker Desktop را نصب و باز کنید، سپس در پوشه اصلی پروژه دستور زیر را اجرا کنید:

```bash
docker compose up --build
```

یا در ویندوز فایل `RUN_PROJECT_WINDOWS.bat` را اجرا کنید. Compose دیتابیس PostgreSQL، Backend و Frontend را بالا می‌آورد. در اولین ایجاد volume دیتابیس، schema و seed خودکار اجرا می‌شوند. راهنمای کامل در `DOCKER_RUN_GUIDE_FA.md` است.

## پیشنهادهای متصل به داده واقعی
- جست‌وجوی محصولات و خدمات در صفحه‌های فهرست، هنگام تایپ از API عمومی همان بخش پیشنهادهای واقعی دریافت می‌کند.
- فیلتر شهر خدمات از `GET /api/v1/suggestions/cities?search=...` پیشنهاد شهرهای ثبت‌شده در پروفایل فروشندگان تأییدشده را می‌گیرد؛ اطلاعات آدرس خصوصی کاربران برگردانده نمی‌شود.
- فهرست دسته‌بندی‌ها از API دسته‌بندی‌ها بارگذاری می‌شود و برای هر زبان فقط فیلد همان زبان نمایش داده می‌شود؛ از جایگزینی خاموش متن انگلیسی در دری/پشتو جلوگیری شده است.

## وضعیت مهم ترجمه
ترجمه کامل و بازبینی‌شده تمام متن‌های ثابت در همه صفحه‌ها، پیام‌های خطا، اعتبارسنجی‌ها و داشبوردها هنوز تکمیل نشده است. همچنین محتوای آزاد ثبت‌شده توسط کاربران (عنوان/توضیح محصول یا خدمت) در schema فعلی فقط یک زبان دارد و خودکار ترجمه نمی‌شود. پیش از ارائه‌ای که در آن الزام «هیچ متن بیگانه‌ای در رابط انتخاب‌شده نباشد» بررسی می‌شود، باید تمام صفحات با هر سه زبان بازبینی و تکمیل شوند.
